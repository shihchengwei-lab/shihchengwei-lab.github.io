How 5 / 100 was counted. arc9 completed its first review on 99 of the 100 PRs. I counted a PR once if arc9’s first review identified an issue absent from Greptile’s review of the same revision. Each counted issue had checkable reproduction evidence from that revision and a rating of P2 or higher in this evaluation. All five PRs came from cases 1–50.

Severity in this evaluation. A P2 issue can cause a supported workflow to fail or require meaningful rework in ordinary use. P3 covers smaller issues.

Cases 1–50. A look back at public feedback found three issues arc9 omitted (install diagnostics (case 9), test wait time (33), vector result ordering (37)) and two it marked for follow-up (query index efficiency (31), migration URL (37)). The evaluation kept these five observations separate from the matched comparison for cases 51–100.

Cases 51–100. I applied the same criteria to findings unique to either tool. Greptile identified five such issues: keyboard focus (case 56), a missing setup requirement (72), terminal text display (73), an incomplete request label (74), and a missing connection diagnostic (96).

Third-party findings. Starting at case 81, I logged individual findings absent from both reviews when a public follow-up comment or commit provided evidence I could check.

Five PRs where arc9 found issues worth fixing

Case 18 · pnpm · Migration instructions

A reinstall left dependencies in the old location.

An isolated run showed that changing the setting and reinstalling left dependencies at the workspace root. A clean reinstall put them where the Electron app needed them.

Case 27 · Mirage · Integration setup

The desktop instructions could lead to the wrong workspace.

In an isolated check, the desktop steps used the already selected remote workspace. Switching the CLI back to local selected the local workspace.

In a separate check, the server rejected a custom public hostname with its default settings. It accepted the hostname after it was added to the allowlist, a step missing from the web setup guide.

Case 32 · Streamplace · Build reuse

A change to a frontend hook could leave the old app running.

The build script’s change check omitted the hook directory. In an isolated run, editing a hook reused the old frontend. An edit in the tracked source directory triggered a rebuild.

How I ran the evaluation

I selected 100 public PRs across 50 repositories in a fixed GitHub search order. Each had a public Greptile summary indicating the PR appeared safe to merge at a specific commit. I saved arc9’s first review before reading the public feedback for that revision, then checked findings against the code, focused tests where practical, and evidence from the same revision.

Case 16 exceeded arc9’s input limit and stayed in the denominator. I kept its smaller rerun outside the first-review score. The results describe this sample of PRs selected for having a favorable Greptile review.

For cases 81–100, I also used the PR description as it stood when Greptile published its favorable assessment. In case 91, arc9’s first review used a later title. I reran it with the title from the time of Greptile’s review and excluded the affected judgment from scoring.
